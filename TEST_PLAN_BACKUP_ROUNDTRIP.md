# Test Plan — Backup round-trip preservation across v1 and v2 (t_e9706055)

Date: 2026-08-04 · Repo: hermes-vault (wt/t_e9706055, base a612315 + cherry-picked b94c8bb v2 codec) · Issue #60

## Scope

Integration tests at the backup/restore boundary proving the v2 codec
migration preserves backup data. No `src/` changes — test-only, plus a
committed v1 fixture under `tests/testdata/`.

## Fixture

`tests/testdata/backup_aesgcm_v1.json` + `backup_aesgcm_v1.salt` are
generated by `tests/testdata/generate_v1_fixture.py` using the vault's own
export path pinned to aesgcm-v1 writes. The fixture deliberately contains:

- a legacy entry WITHOUT a `crypto_version` key (pre-#60 shape; import must
  default it to aesgcm-v1)
- an explicit `aesgcm-v1` entry with scopes/tags/notes (authorization
  metadata bound into v2 AAD)
- one lease record

The generator is re-runnable (fresh UUIDs per run); tests resolve ids from
the fixture instead of hardcoding them, and copy the salt (never mutating
the committed file).

## Test matrix (tests/test_backup_roundtrip_v1_v2.py)

| # | Test | Layer | Proves |
|---|------|-------|--------|
| 1 | v1 fixture restores payload bytes + metadata | L4 | payload bytes byte-identical, secrets decode, AAD-bound metadata + tags/notes survive |
| 2 | legacy entry (no crypto_version) defaults to v1 | L4 | pre-#60 backups open |
| 3 | v1 fixture restore preserves lease | L4 | lease metadata survives |
| 4 | v1 fixture verify + dry-run decryptable | L4 | verify_backup_file/restore_dry_run on committed fixture |
| 5 | v2 backup round-trips unchanged | L4 | v2 payload byte-identical, secret + AAD metadata survive fresh restore |
| 6 | v2 backup verify + dry-run | L4 | v2 verify path decryptable |
| 7 | v2 restore over existing row rebinds AAD, preserves secret | L4 | import rebind to destination metadata |
| 8 | v1 fixture openable after v2 active | L4 | per-row dispatch; v1+v2 coexist, new writes are v2 |
| 9 | v1 fixture verify still decryptable with v2 env | L4 | read path version-aware |
| 10 | v1 fixture -> v2-format export preserves data | L4 | format migration keeps payload bytes + secrets |
| 11 | v1 export round-trip preserves all credentials | L4 | no-v2-writes baseline cycle |

## Acceptance criteria mapping

- "a v1 fixture restores unchanged" → tests 1–4
- "a v2 backup round-trips unchanged" → tests 5–7
- "any format migration preserves backup data" → tests 10–11 (plus 8–9
  proving v1 stays open after v2 is active)
